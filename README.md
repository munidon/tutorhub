# TutorHub

**1인 과외 선생님을 위한 일정·조율·정산 관리 서비스.**

선생님은 수업 일정을 캘린더로 관리하고, 학부모는 발급받은 계정으로 자녀의 일정을
확인하거나 추가·변경·취소를 **요청**합니다. 선생님이 승인하면 반영되고, 요청이 들어오면
**텔레그램으로 알림**이 옵니다. 월별 **수업료 정산**과 **입금 확인**까지 한 곳에서 처리합니다.

> 문자로 일정·보강·정산을 주고받던 과정을 하나의 "단일 진실 공급원"으로 모으는 것이 목표입니다.

---

## 주요 기능

- **캘린더 일정 관리** — 정규/추가 수업 등록, 클릭으로 시간 변경·취소·삭제. 동시간대 중복 예약은 자동 차단.
- **반복 일정 템플릿** — 학생별 고정 수업(요일·시각·길이)을 저장해 두고, 수업 추가 시 한 번에 적용.
- **학부모 계정 & 데이터 격리** — 선생님이 계정을 발급. 학부모는 **본인 자녀 일정만** 볼 수 있음(DB 차원에서 강제).
- **조율 요청 워크플로우** — 학부모의 추가/변경/취소 요청 → 선생님 승인·반려(사유) → 즉시 반영.
- **텔레그램 알림** — 새 요청이 들어오면 선생님에게 "어느 학생의 무슨 요청 + 메시지"가 푸시됨.
- **수업료 정산** — 정규 수업료, 변경분(추가·변경·취소) 집계, 미정산분의 다음 달 **이월**, 현금 등 **직접 정산** 처리.
- **입금 확인** — 선생님이 학생×월 입금을 확인하면 학부모 청구서에 "정규 수업료 입금 확인되었습니다!" 표시. 학부모는 계좌번호 **복사** 버튼으로 입금.
- **일정 내보내기** — 캘린더에서 특정 학생을 고르면 그 달 일정을 **텍스트로 복사**(취소 수업 제외)하거나, 전체 확정 수업을 **iCal(.ics) 파일**로 내려받아 맥·아이폰 캘린더 앱에 가져올 수 있음.
- **월별 전환** — 캘린더·정산·요청 내역 모두 월 단위로 넘겨 볼 수 있음.

---

## 동작 방식 (개념)

- **역할은 2가지**: 선생님(1명) · 학부모(N명). 학부모 1계정에 자녀 여러 명을 연결할 수 있습니다.
- **선생님이 직접 한 변경은 즉시 반영**, **학부모의 요청은 승인 후 반영**됩니다.
- 모든 데이터는 Supabase(Postgres)에 저장되며, **행 단위 보안(RLS)** 으로 학생 간 데이터가 철저히 분리됩니다.
- 시간은 내부적으로 UTC로 저장하고 화면에는 항상 **한국 시간(KST)** 으로 표시합니다.

기술 스택: Next.js(App Router) · TypeScript · Tailwind CSS · Supabase(Auth/Postgres/RLS) · Telegram Bot(Supabase Edge Function).

## 설치 & 적용 (최초 1회)

기술적인 설정 단계입니다. 한 번만 해두면 이후엔 브라우저에서 쓰기만 하면 됩니다.

### 1. 사전 준비
- Node.js 20 이상
- [Supabase](https://supabase.com) 프로젝트 1개 (무료 플랜으로 충분)
- (알림을 쓸 경우) [Supabase CLI](https://supabase.com/docs/guides/cli) 와 텔레그램 봇

### 2. 의존성 설치 & 환경변수
```bash
npm install
cp .env.local.example .env.local
```
Supabase 대시보드 › **Project Settings › API** 의 값으로 `.env.local` 을 채웁니다.

| 변수 | 설명 |
|------|------|
| `NEXT_PUBLIC_SUPABASE_URL` | 프로젝트 URL (공개) |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | anon/publishable 키 (공개) |
| `SUPABASE_SERVICE_ROLE_KEY` | service_role 키 — **서버 전용, 절대 노출 금지** (학부모 계정 발급·비번 초기화에 사용) |
| `NEXT_PUBLIC_PARENT_EMAIL_DOMAIN` | 학부모 합성 이메일 도메인 (기본 `parents.tutorhub.local`) |

> 학부모는 이메일이 없어도 됩니다. 선생님이 정한 **로그인 아이디**에 위 도메인을 붙여 내부 계정으로 매핑하며, 학부모는 그 아이디로만 로그인합니다.

### 3. 데이터베이스 준비 (마이그레이션)
`supabase/migrations/` 의 SQL을 **번호 순서대로 전부** 실행하고, 마지막에 `supabase/seed.sql` 을 실행합니다.

- **대시보드 SQL Editor** 에 차례로 붙여넣어 실행하거나,
- **CLI**:
  ```bash
  supabase link --project-ref <프로젝트-REF>
  supabase db push     # migrations 적용 (seed.sql 은 대시보드/psql 로)
  ```

### 4. 선생님 계정 만들기 (1회)
1. 대시보드 › **Authentication › Users › Add user** 로 선생님 이메일·비밀번호 계정을 생성합니다.
2. `seed.sql` 하단 주석의 `update ... set role = 'teacher'` 문에서 이메일을 본인 것으로 바꿔 한 번 실행해 **선생님 권한으로 승격**합니다.

### 5. 텔레그램 알림 연결 (선택, 권장)
학부모 요청을 놓치지 않으려면 연결을 권장합니다.

1. 텔레그램에서 [@BotFather](https://t.me/BotFather) 로 봇을 만들고 **봇 토큰**을 받습니다.
2. 만든 봇과 대화를 시작(아무 메시지나 전송)한 뒤, 브라우저에서
   `https://api.telegram.org/bot<토큰>/getUpdates` 를 열어 `result[].message.chat.id` 값(**chat_id**)을 확인합니다.
3. Edge Function 시크릿 등록 후 배포:
   ```bash
   supabase secrets set TELEGRAM_BOT_TOKEN=<토큰> TELEGRAM_CHAT_ID=<chat_id> SITE_URL=https://<배포주소>
   supabase functions deploy notify-telegram --no-verify-jwt
   ```
4. 대시보드 › **Database › Webhooks › Create** 에서
   `public.requests` 테이블의 **INSERT** 이벤트 → Supabase Edge Functions `notify-telegram` 으로 연결합니다.

이제 학부모 요청이 들어오면 다음과 같은 알림이 옵니다:
```
📌 윤지호 학부모님의 새 변경 요청이 도착했습니다.
요청 메세지: 다음 주는 화요일로 옮길 수 있을까요?

승인하기 ▶ https://<배포주소>/admin/requests
```

### 6. 실행
```bash
npm run dev     # 개발 서버 (http://localhost:3000)
```
항상 접속 가능하게 하려면 **Vercel** 등에 배포하고, 같은 환경변수를 호스팅 환경에 등록하면 됩니다.
(배포 주소를 텔레그램 `SITE_URL` 시크릿에도 반영하세요.)

## 사용법 — 선생님

로그인하면 상단 탭으로 이동합니다: **정산 · 캘린더 · 요청 · 학생/계정 · 설정**

1. **학생/계정** — 학부모 계정을 발급(로그인 아이디·초기 비밀번호)하고, 자녀(학생)를 추가합니다. 학생마다 **캘린더 색상**과 **시급**을 지정하세요. 발급한 아이디·비밀번호는 학부모에게 직접 전달합니다.
2. **설정** — 학부모 청구서에 보일 **입금 계좌**(은행·계좌번호·예금주)를 입력하고, 학생별 **반복 일정 템플릿**(요일·시작 시각·수업 시간)을 등록합니다.
3. **캘린더** — `+ 수업 추가` 로 일정을 등록합니다. **템플릿 적용**을 고르면 현재 보고 있는 달에서 해당 요일의 가장 빠른 날(이미 등록된 날은 건너뜀)로 자동 입력됩니다. 등록된 수업을 클릭하면 **시간 변경·취소·삭제**, 그리고 추가/변경분의 **직접 정산(현금 수령)** 처리를 할 수 있습니다.
   - *취소* 는 정산에 반영되는 기록이고, *삭제* 는 잘못 넣은 수업을 흔적 없이 지웁니다.
   - **학생 보기**에서 특정 학생을 고르면 두 가지 내보내기 버튼이 나타납니다. *일정 추출* 은 지금 보고 있는 달의 일정을 `6/7(일): 14:00~17:00` 형식 텍스트로 클립보드에 복사합니다(취소 수업 제외 — 학부모에게 그대로 전달 가능). *캘린더 내보내기(.ics)* 는 그 학생의 전체 확정 수업을 `.ics` 파일로 내려받아, 파일을 열면 맥·아이폰 **캘린더 앱**에 그대로 가져올 수 있습니다.
4. **요청** — 학부모의 대기 중 요청을 **승인/반려(사유)** 합니다. 승인하면 캘린더에 즉시 반영됩니다. (대기 요청은 월과 무관하게 항상 표시, 처리 완료 내역은 월별로 조회)
5. **정산** — 학생별로 그 달의 **정규 수업시간·수업료**, **변경 수업시간**(추가/변경/취소), 다음 달로 넘어가는 **이월 수업료**를 봅니다. 입금을 받으면 **입금 확인** 버튼을 눌러 학부모 청구서에 반영합니다.

## 사용법 — 학부모

상단 탭: **캘린더 · 요청 내역 · 설정**

- **캘린더** — 자녀의 일정을 색상·상태로 봅니다. 수업을 누르면 **시간 변경/취소를 요청**할 수 있고, `+ 추가 수업 요청` 으로 보강 등을 요청합니다(선생님께 보낼 메시지 첨부 가능). 아래에는 그 달의 **수업료 안내**와 **입금 계좌**(계좌번호 복사 버튼)가 함께 표시됩니다.
- **요청 내역** — 보낸 요청의 상태(대기/승인/반려/철회)와 처리 시각을 월별로 확인합니다. 대기 중 요청은 **요청 취소**(철회)할 수 있습니다.
- **설정** — 본인 비밀번호를 변경합니다.

## 비밀번호 & 계정 관리

- **학부모 비밀번호 변경**: 학부모가 직접 *설정* 탭에서 변경(현재 비밀번호 확인 후).
- **비밀번호 분실**: 학부모가 선생님께 문의하면, 선생님이 *학생/계정* 탭에서 **비밀번호 초기화**(고정 초기값 `123456`) → 학부모가 로그인 후 설정에서 변경.
- **계정 삭제**: *학생/계정* 탭에서 계정과 연결된 자녀·일정·요청을 함께 영구 삭제할 수 있습니다.

## 수업료 정산 모델 (요약)

- **정규 수업료** = 정규 수업시간 × 시급 + **전월 이월**. 정규 수업은 취소·변경돼도 *당초 계획 시간*을 정규시간으로 유지합니다.
- **변경 수업시간** = 추가(＋) · 변경(후−전) · 취소(−) 를 모두 반영한 그 달의 조정분.
- **이월 수업료** = 아직 정산하지 않은 변경분 × 시급 → 다음 달 정규 수업료에 더해집니다.
- **직접 정산**: 현금 등으로 이미 받은 변경분은 캘린더에서 *수령 처리* 하면 이월에서 제외됩니다. 그 달 변경분을 모두 정산하면 안내 문구만 표시됩니다.

## 데이터 보안

- **격리**: 학부모는 본인 자녀의 행만 조회 가능(RLS). 다른 학생 데이터는 쿼리 자체가 차단됩니다.
- **비밀번호**: Supabase Auth가 해시로 관리하며 앱 DB에 평문 저장하지 않습니다.
- **승인 처리**: 요청 결정은 트랜잭션 RPC로 원자적으로 처리되어, 학부모 철회와 동시에 일어나도 데이터가 어긋나지 않습니다.
- **중복 예약 방지**: 같은 시간대에 확정 수업이 겹치지 않도록 DB에서 강제합니다.
